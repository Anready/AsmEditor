# AsmEditor — план развития

Все пункты прежнего списка реализованы (см. README). Ниже — что из них сделано не полностью или не проверено,
и что можно делать дальше.

## Сделано с оговорками

- **Шаг после «Паузы».** Медленный `SetThreadContext` больше не вызывается для потока, который не сообщал о событии:
  если пауза пришлась на системный вызов (DebugBreakProcess), шаг ставит временные точки на строки исходника и
  ждёт возврата в свой код. Тест `DebuggerStepAfterPauseIsFast`: следующий шаг ~15 мс. Сценарий «тяжёлый цикл без
  системных вызовов» отдельно не воспроизводился.
- **Отладка 32-битного кода** (WOW64: `Wow64GetThreadContext`, `STATUS_WX86_BREAKPOINT`/`SINGLE_STEP`,
  4-байтовые указатели) — сквозным тестом проверена только 64-битная программа.
- **Точки останова на данные** ставятся в отладочные регистры потока, который остановился (обычно главного);
  в других уже работающих потоках — нет (SetThreadContext там очень медленный).
- **Стек вызовов** строится по адресам возврата в стеке (у NASM-кода нет таблиц раскрутки); прямые `call`
  проверяются по цели, косвенные — нет, поэтому после косвенных вызовов возможны лишние кадры.
- **Linux через WSL** (сборка `-f elf64`, линковка в WSL, запуск, gdb в терминале) не проверен: на машине
  разработки нет дистрибутива WSL. Отладка Linux-программ — в консольном gdb, без панелей редактора.
- **Локализация**: интерфейс (меню, панели, диалоги, сообщения сборки и отладчика) переведён; справочник по
  инструкциям и часть редких сообщений (переименование, сборка в toolchain.cpp) остаются на русском.
- **Установщик** не делался — вместо него портативный zip (`build.bat package`).
- **Проверка обновлений** читает страницы nasm.us и scintilla.org; при смене их разметки перестанет находить версию.
- **CI** (`.github/workflows/build.yml`) написан, но не запускался: у репозитория пока нет удалённого GitHub.

## Проверено (тестами и вручную)

Условные точки останова, точки останова на данные, стек вызовов, изменение регистров, статистика завершения —
сквозной тест отладчика (`build.bat test`, 143 проверки). Вручную по снимкам экрана: вкладки нижней панели,
структура файла, сворачивание, подсветка вхождений, полоса отметок, панель отладки (регистры, наблюдение, код),
выпадающие списки на панели, светлая тема, английский интерфейс, Ctrl+наведение и Ctrl+клик, строка синтаксиса в
подсказке, текст отказа при конфликте имён в переименовании. «Не собирать этот файл» — юнит-тест `Project::Collect`.

## Что дальше

Сверху — то, что даст больше всего пользы при небольшом объёме работы.

### 1. Доделать начатое

- **Сквозной тест 32-битной отладки** (`-f win32`, шаблон «MSVC link x86»), как уже есть для 64-битной.
- **Запустить CI**: создать репозиторий на GitHub, отправить код, убедиться, что `build.yml` собирает и проходит тесты.
- **Отладка Linux-программ в панелях редактора**: управлять gdb через gdb/MI вместо консольного режима — регистры,
  стек вызовов, наблюдение и точки останова как для Windows. Нужен дистрибутив WSL (например, Ubuntu) для проверки.
- **Точки останова на данные во всех потоках**, а не только в остановившемся.
- **Стек вызовов по `.pdata`** для кода, где есть таблицы раскрутки (C-файлы в проекте).
- **Перевод справочника по инструкциям на английский** и оставшихся сообщений (переименование, toolchain.cpp).

### 2. Отладчик

- **Шаг назад**: запоминать регистры и изменённую память на каждом шаге и откатываться к предыдущему состоянию.
- **Окно «Флаги» с пояснением переходов**: почему условный переход сработает или нет (`jl`: SF ≠ OF → переход).
- **Профилировщик**: сколько раз выполнилась каждая строка и сколько времени это заняло — числа прямо в редакторе.
- **Точки останова с действием** (logpoints): печатать значение выражения в «Отладочный вывод» без остановки.

### 3. Редактор

- **Подсказка аргументов при наборе `call функция`**: какие регистры уже заполнены выше, какие забыты;
  проверка числа аргументов по прототипу.
- **Быстрые исправления по ошибкам**: «добавить `extern printf`», «добавить `sub rsp, 40`» и т. п.
- **Анализатор кода**: сохраняемый регистр (rbx, rsi, rdi, rbp, r12–r15) изменён и не восстановлен; `div` без
  обнуления rdx; недостижимый код после `ret`/`jmp`.
- **Значение выделенного выражения** во время отладки (выделить `[rsp+8]` — увидеть значение).

### 4. Обучение

- **Пошаговые уроки** («урок 1: регистры и mov…»): объяснение и задачи с автопроверкой.
- **Анимация стека** при `push`, `pop`, `call`, `ret` во время отладки.
- **Больше учебных задач**: строки, массивы, рекурсия, работа с файлами.
- **Экспорт результатов проверки** для преподавателя (кто какие задачи решил).

### 5. Инфраструктура

- **Установщик** (Inno Setup или MSI) и ассоциация файлов `.asm` с редактором.
- **Автотесты интерфейса** в CI: запуск окна, команды через WM_COMMAND, сравнение снимков экрана.
- **Релизы на GitHub** с автоматической сборкой и подписью по тегу.

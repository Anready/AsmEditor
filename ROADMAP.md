# AsmEditor — что ещё можно сделать

Список идей по развитию редактора. Сверху — то, что даст больше всего пользы при небольшом объёме работы.

## 1. Известные недоработки (стоит закрыть первыми)

- **Шаг после «Паузы» тяжёлого цикла.** Если программа долго крутила цикл, первый шаг после паузы занимает
  4–6 секунд (так медленно Windows выполняет `SetThreadContext`). Можно попробовать аппаратные точки останова
  через отладочные регистры или ставить `int3` на следующую инструкцию — для этого нужен декодер длины инструкций.
- **Сообщения отладчика внутри вывода программы.** Если отладчик печатает в консоль, пока программа работает,
  её вывод «фиксируется» выше. Программы, которые сами двигают курсор по экрану, после этого могут
  отрисоваться со сдвигом. Решение: отдельные вкладки «Вывод» и «Терминал» в нижней панели.
- **Первый показ списка автодополнения** иногда мелькает со светлой полосой прокрутки. Нужно применять
  тёмную тему до первого показа (перехватить создание окна `ListBoxX`).
- **Не проверено вживую:** Ctrl+клик и подчёркивание при наведении для перехода к определению; пункт дерева
  «Не собирать этот файл»; текст окна отказа при конфликте имён в переименовании; голубая строка синтаксиса
  в подсказках. Стоит пройти руками.
- **Отладка 32-битного кода** (`-f win32`) не поддерживается: нужны `Wow64GetThreadContext` и обработка
  `STATUS_WX86_BREAKPOINT`.

## 2. Отладчик

- **Изменение регистров и памяти** прямо в панели (двойной клик по значению → ввод нового).
- **Окно дизассемблера** рядом с исходником: видно, во что развернулись макросы. Можно использовать
  встроенный `ndisasm` из NASM или подключить библиотеку Zydis.
- **Стек вызовов (call stack)** по цепочке адресов возврата и `rbp`: где мы и кто нас вызвал.
- **Условные точки останова** (`rcx == 5`, «сработать на 10-й раз») — выражения уже вычисляются в панели памяти.
- **Точки останова на данные (watchpoints)** через отладочные регистры DR0–DR3: остановиться, когда изменилась
  переменная `counter`.
- **Список наблюдения (watch)**: несколько выражений вида `[rsp+8]`, `msg`, `rax*2`, которые обновляются
  на каждой остановке.
- **«Выполнить до курсора»** (Ctrl+F10) и **«Перенести выполнение сюда»** (сменить `rip`).
- **Показ памяти в разных видах**: байты / слова / dword / qword / float / double / строка.
- **Подсветка изменённых байтов** в дампе памяти между остановками.
- **Вывод `OutputDebugString`** в отдельную вкладку.

## 3. Редактор

- **Структура файла (outline)**: список меток, функций и секций в боковой панели с переходом по клику.
- **Форматирование кода**: выравнивание мнемоник, операндов и комментариев по колонкам (настраиваемые отступы).
- **Сворачивание блоков** (folding): `%macro … %endmacro`, `%if … %endif`, `%rep`, тела функций между метками.
- **Подсветка парных скобок и директив**: `[ ]`, `%if/%endif`, `%macro/%endmacro`.
- **Подсветка всех вхождений** слова под курсором (как в VS Code), без вызова Shift+F12.
- **Сниппеты**: «функция Win64 с прологом и эпилогом», «цикл со счётчиком», «вызов printf», «шаблон программы».
- **Многокурсорное редактирование** (в Scintilla уже есть, нужно включить и привязать клавиши).
- **Поиск по всем файлам проекта** (Ctrl+Shift+F) с заменой.
- **Палитра команд** (Ctrl+Shift+P) и быстрое открытие файла по имени (Ctrl+P).
- **Подсказка по макросу**: при наведении показывать тело `%macro`/`%define`.
- **Показ значения `equ`/`%define`** при наведении (например, `LIMIT = 10`).
- **Миникарта или полоса ошибок** у вертикальной прокрутки: отметки строк с ошибками и точками останова.
- **Автосохранение** и восстановление несохранённых файлов после сбоя.
- **Отслеживание изменений файлов на диске**: предложить перезагрузить вкладку, если файл изменили снаружи.

## 4. Сборка и запуск

- **Конфигурации запуска**: аргументы командной строки, рабочая папка, переменные окружения, файл для stdin.
- **Несколько программ в проекте**: выпадающий список «что запускать» вместо одного главного файла.
- **Профили сборки** Debug/Release: с отладочной информацией и без, разные флаги NASM и линкера.
- **Сборка DLL и статических библиотек** (`/dll`, `lib.exe`), а не только exe.
- **Поддержка Linux-ассемблера** (`-f elf64`) через WSL: сборка `ld`, запуск и отладка через `gdb`.
- **Пользовательские задачи**: произвольные команды до и после сборки (например, копировать ресурсы).
- **Окно ошибок** — отдельный список всех ошибок и предупреждений проекта с переходом, а не только консоль.
- **Время выполнения программы** и пиковое потребление памяти — в строке «Процесс завершён».

## 5. Обучение и справка

- **Расширить справочник** до полного набора инструкций (AVX/AVX2, все x87, системные), с примерами кода.
- **Подсказка по WinAPI и функциям C**: при наведении на `printf`, `WriteFile` показывать аргументы
  и в каких регистрах их передавать по соглашению Win64.
- **Проверка соглашения о вызовах**: предупреждать, если перед `call` стек, вероятно, не выровнен на 16
  или не выделено теневое место.
- **Визуализация стека** во время отладки: кадры функций, адреса возврата, сохранённые регистры.
- **Шаблоны проектов**: «Hello world», «ввод/вывод через scanf/printf», «чистый WinAPI», «работа с файлами»,
  «использование SSE».
- **Встроенные примеры и задачи** с проверкой результата (для учебных курсов).

## 7. Качество и поддержка

- **Автотесты**: токенизатор, разбор ошибок NASM, поиск вхождений, переименование, эмулятор терминала —
  юнит-тесты без UI; сценарии UI на основе текущего тестового скрипта.
- **CI-сборка** (GitHub Actions) с артефактом `AsmEditor.exe`.
- **Git-репозиторий** — сейчас проект не под контролем версий.
- **Лог работы** редактора для диагностики (уже есть трассировка отладчика через `ASMEDITOR_TRACE=1`).
- **Разбить `mainwindow.cpp`** (около 3000 строк) на части: панели, сборка, отладка, навигация.
